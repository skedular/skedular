# Gateway Agent Notes

This file is the entry point for AI agents working in `gateway/`.

## Purpose

- `gateway/` is the GraphQL federation entry point for the entire platform.
- It uses **HotChocolate Fusion** to compose subgraph schemas from all domain APIs into a single federated schema.
- It also uses **YARP** (reverse proxy) to route non-GraphQL HTTP traffic to the correct downstream service.

## Structure

```
gateway/
  apis/
    Gateway/
      Controllers/       # Minimal REST controller (health, diagnostics)
      Configurations/    # Gateway-specific config binding
      gateway.fgp        # Compiled fusion gateway package (generated — do not hand-edit)
      Program.cs
      ServiceDiscoveryConfigurationRewriter.cs
```

## GraphQL Fusion

- The gateway reads a compiled `.fgp` (Fusion Gateway Package) embedded in the assembly.
- The `.fgp` is regenerated by running `scripts/generate-graphql.sh`, which packs all subgraph schemas.
- Do not hand-edit `gateway.fgp` or any per-API `schema.graphql` files.
- If a subgraph schema changes, run `scripts/generate-graphql.sh` from the repo root to recompose the gateway schema.

## Service Discovery

- `ServiceDiscoveryConfigurationRewriter` rewrites downstream service URLs from Aspire service-discovery names to real
  URLs at runtime.
- Do not hardcode downstream service URLs in the gateway configuration; always use service-discovery names.

## YARP Reverse Proxy

- REST/HTTP traffic routing is configured in `appsettings.json` under the `ReverseProxy` section.
- If a new domain API is added, add a corresponding YARP route there too.

## Auth / Security

- The gateway enforces JWT auth via `Enterprise.Shared` security middleware.
- It delegates authentication context to subgraphs via request propagation (`RequestContextPropagationHandler`).
- Do not add domain-specific business logic to the gateway; it should remain a pure routing and composition layer.

## Agent Rule

- Keep the gateway as a thin composition layer — no domain business logic here.
- If a GraphQL type or field needs to change, change the relevant subgraph API, then regenerate via `scripts/generate-graphql.sh`.
- If a REST route is missing, add it in the `ReverseProxy` configuration section, not by adding a new controller.
- Run `scripts/generate-graphql.sh` after any subgraph schema change; never patch `gateway.fgp` by hand.
