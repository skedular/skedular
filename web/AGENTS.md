# Web Monorepo Agent Notes

This file is the entry point for AI agents working in `web/`.

## Structure

```
web/
  apps/
    webapp/        # Main Next.js customer-facing and operator web app
    webapphelp/    # Supplementary help/documentation app
  infrastructure/ # Shared web infrastructure helpers
  package.json
  pnpm-workspace.yaml
  turbo.json
```

## Technology Stack

- **Package manager**: pnpm with workspaces
- **Build orchestration**: Turborepo (`turbo.json`)
- **Framework**: Next.js (App Router) in `web/apps/webapp`
- **GraphQL client**: Relay (`react-relay`, generated types under `src/queries/__generated__/`)
- **UI library**: MUI (Material UI) — but use Skedular typography wrappers, not `@mui/material/Typography` directly
- **Type generation**: OpenAPI → TypeScript via `web/apps/webapp/scripts/generate.sh`

## Code Generation

- TypeScript API clients are generated by `web/apps/webapp/scripts/generate.sh`.
- GraphQL Relay artifacts are generated from the gateway schema; regenerate after any schema change.
- Do not hand-edit files under `src/queries/__generated__/` or `src/clients/` if those are generated.
- Run `make generate` from the repo root to regenerate all surfaces (API definitions → GraphQL schema → web artifacts) in the correct order.

## Agent Rule

- Do not import `@mui/material/Typography` directly in feature components; use the Skedular wrappers in `@/components/commons`.
- Do not hand-edit generated type files; change the source and regenerate.
- Changes to backend GraphQL enums or fields require regenerating the Relay artifacts to keep web types in sync.
- Keep `pnpm-lock.yaml` consistent; use `pnpm install` rather than `npm install` or `yarn`.
- For broad UI work in `web/apps/webapp`, follow `web/apps/webapp/docs/ui-redesign-program.md`.
- The long-term direction is a reusable web design system under `web/packages/*`, but only extract patterns that are
  already stable across more than one domain surface.
- The current testing direction is Vitest + React Testing Library from `web/apps/webapp`, with coverage allowed to
  extend into Relay-free workspace packages such as `web/packages/ui`.
- In `web/apps/webapp`, prefer Relay colocation. Fragments and small queries should live beside the component that uses
  them instead of being abstracted into reusable fragment files by default.
