# NATS JetStream Messaging

`Enterprise.Shared.Nats` provides the shared NATS JetStream messaging boundary.

## Registration

Call `AddNatsMessaging` with a `Nats` configuration section. Registration creates the shared connection and messaging
services; it does not create or update JetStream resources.

## Payloads

The low-level publisher and subscriber APIs use raw bytes. Typed event messages use the protobuf serializer over
generated `Google.Protobuf.IMessage<T>` types. Event contracts remain owned by `api-definitions/events` and are
generated by the consuming project at build time.

## Resources

Use `INatsJetStreamProvisioner` or `INatsHelper.CreateResourcesForEventAsync<TEvent>` against a running JetStream server
to create or update streams and durable consumers. `TEvent` metadata is used for resource names only; the helper does
not publish event instances.

## Consumer Behavior

Consumers use one durable pull consumer and request one message at a time. The current handler must complete, including
acknowledgment or reliable forwarding, before another message is requested from the same subject.

Non-reliable consumers leave failures unacknowledged and receive the same message again until processing succeeds. They
do not publish retry or dead-letter messages.

Reliable consumers forward failures through the derived ordered retry subjects and then the dead-letter subject. The
original message is acknowledged only after forwarding succeeds. Forwarded messages carry the UTF-8 `retry-timestamp`
header, and retry consumers apply the Kafka-compatible exponential delay before processing.

NATS client reconnect is supported, but the shared library does not implement an application-level outbox or operation
retry loop.
