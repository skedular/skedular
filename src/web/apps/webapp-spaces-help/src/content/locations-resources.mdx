# Locations And Resources

Locations and resources are the places and items your marketplace organization can offer to customers.

## Locations

A location is a place your organization manages. It may be a co-working site, a building, a floor, or another bookable place.

Use the locations page to review existing locations. Use add-marketplace location when a new public marketplace location should be created.

## Location Detail

The location detail page helps operators review the location and related setup.

Check:

- name and address
- public readiness
- resources
- floor plan or zone information
- booking and availability context

## Resources

Resources are the bookable items or spaces inside a location. They may become part of a product offer.

Use the add resource flow when customers or operator bookings need a new bookable item.

## Zones And Floor Plans

Zones and floor plans make larger locations easier to understand. They help operators manage layout and help customers understand the space later.

## Expected Result

Locations and resources should be clear enough for products and bookings to use them safely.

## Location Setup Checklist

Before using a location in products, check:

- name customers can understand
- address or public place description
- whether it is ready for marketplace use
- resources that can be sold or booked
- zones or floor plan information
- availability expectations
- any access notes customers need

If a location is only for internal company use, it probably belongs in Teams, not Spaces.

## Resource Setup Checklist

Before using a resource in a product, check:

- what the resource is
- where it is inside the location
- whether customers should see it directly
- capacity or usage limits
- availability
- whether it appears on a floor plan
- whether it supports one-time booking, subscriptions, or both

Resources should be named for customers and operators. A name like "Room 3 - 8 people" is more useful than a short internal code.

## How Locations, Resources, And Products Fit Together

Think of the setup in layers:

1. The **location** is the place.
2. The **resource** is what can be used inside the place.
3. The **product** is the offer a customer can buy.
4. The **booking or subscription** is the customer's purchase record.

If one layer is unclear, the layers after it become harder to support.

## Common Problems

| Problem                             | What to check                                                                  |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| A product points to the wrong place | Check the product's location/resource connection.                              |
| Customers cannot book a resource    | Check resource availability and product rules.                                 |
| A floor plan is confusing           | Review zone names and resource labels.                                         |
| A resource should not be public     | Remove it from marketplace product setup or move the work to Teams if private. |
