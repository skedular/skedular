# Locations

## Overview

A location represents a physical place where bookable resources exist.

Locations are one of the core building blocks of Skedular and are available in:

- **Skedular Teams**
- **Skedular Spaces**
- **Skedular Host**

Every resource in Skedular belongs to a location. Without a location, resources cannot exist.

A location defines where resources are, when they are available, and how users interact with them.

---

# Why Locations Exist

Locations provide the physical context for resources.

They allow organizations to manage:

- Offices
- Coworking spaces
- Buildings
- Floors
- Studios
- Meeting venues
- Warehouses
- Event spaces
- Storage facilities
- Any other physical place that contains bookable resources

Each location has its own configuration and operational settings.

---

# How Locations Work

Locations belong to a single organization.

An organization may contain:

- One location
- Multiple locations

Each location operates independently while sharing organization-wide settings such as members, tags, and zones.

---

# Time Zone

Every location has its own time zone.

The time zone determines how bookings, opening hours, and availability are calculated for that location.

This allows organizations operating across multiple regions or countries to manage bookings accurately using each location's local time.

---

# Opening Hours

Each location manages its own opening hours.

Opening hours determine when resources at the location are available for booking.

Different locations within the same organization can have completely different operating hours.

For example:

- Auckland Office
  - Monday to Friday
  - 8:00 AM to 6:00 PM

- Sydney Office
  - Monday to Friday
  - 7:00 AM to 5:00 PM

Opening hours are configured independently for each location.

---

# Resources

Locations contain one or more resources.

Examples include:

- Desks
- Meeting rooms
- Parking spaces
- Equipment
- Studios
- Private offices
- Event spaces

Every resource belongs to exactly one location.

Resources cannot exist without a location.

---

# Floor Plans

Each location can contain one or more floor plans.

Floor plans provide a visual representation of the physical space and allow users to book resources directly from an interactive map.

Examples include:

- Ground Floor
- Level One
- Building A
- Building B

Multiple floor plans can be created for a single location.

---

# Physical Address

Locations store their physical address.

This information typically includes:

- Street address
- City
- State or region
- Country
- Postal code
- Geographic coordinates

The address helps users locate the venue and supports mapping and navigation features.

---

# Tags and Zones

Resources within a location can use the organization's shared:

- Tags
- Zones

Locations do not create their own tags or zones.

Instead, they reuse the organization-wide definitions to ensure consistency across all locations.

---

# Restricted Information

Locations can store private operational information that is not intended for public viewing.

Examples include:

- Wi-Fi passwords
- Door access instructions
- Alarm codes
- Reception instructions
- Operating procedures
- Internal notes
- Customer arrival information

This information can be shared with authorised users or customers when appropriate, depending on the organization's policies and booking workflows.

---

# Managing Locations

Locations are managed from the organization.

Administrators can:

- Create new locations.
- Edit existing locations.
- Configure opening hours.
- Manage floor plans.
- Add or remove resources.
- Update the physical address.
- Manage restricted information.
- Archive or delete locations when required.

---

# Creating a Location

To create a location:

1. Open your organization.
2. Navigate to **Locations**.
3. Select **Create Location**.
4. Enter the location details.
5. Configure the physical address.
6. Select the location's time zone.
7. Configure opening hours.
8. Add floor plans if required.
9. Create resources.
10. Save the location.

The location is then ready to accept bookings.

---

# Best Practices

For the best experience:

- Create one location for each physical site.
- Configure the correct time zone.
- Keep opening hours up to date.
- Add floor plans to improve the booking experience.
- Maintain accurate address information.
- Keep restricted information current.
- Organise resources clearly within each location.

---

# Things to Know

- Every location belongs to a single organization.
- Organizations can have multiple locations.
- Every location has its own time zone.
- Every location has its own opening hours.
- Every resource belongs to exactly one location.
- Resources cannot exist without a location.
- Locations can contain multiple floor plans.
- Locations can store restricted operational information.
- Resources use the organization's tags and zones.

---

# Example

A company operates offices in Auckland and Wellington.

Each office is created as a separate location.

The Auckland office has:

- Its own opening hours.
- Two floor plans.
- Fifty desks.
- Five meeting rooms.
- Separate Wi-Fi credentials.

The Wellington office has:

- Different opening hours.
- One floor plan.
- Twenty desks.
- Two meeting rooms.

Although both locations belong to the same organization, each operates independently while sharing the same members, tags, and zones.
