# Implementation Plan: Web App Component Cleanup

**Branch**: `042-web-app-cleanup` | **Date**: 2026-08-19 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/042-web-app-cleanup/spec.md`

## Summary

Audit the four application-owned web surfaces (`webapp`, `webapp-spaces`, `webapp-teams`, and `webapp-host`) from route entry points outward, classify components and dependent files by repository reachability, remove only confirmed dead application code, and validate that the protected route surface remains intact. Shared packages, UI components, generated artifacts, dependencies, and ambiguous files remain outside the deletion set.

## Technical Context

**Language/Version**: TypeScript 6.0.3, React 19.2.6, Next.js 16.2.6  
**Primary Dependencies**: Next.js App Router, Relay compiler, Vitest, React Testing Library, Playwright, ESLint, pnpm/Turbo workspace tooling  
**Storage**: N/A; checked-in application source and tests only  
**Testing**: Per-app `lint`, `test`, `build`, relevant Playwright suites, and route inventory comparison  
**Target Platform**: Four deployed Next.js web applications  
**Project Type**: Multi-application frontend workspace  
**Performance Goals**: No user-facing performance change; no route availability or build regression  
**Constraints**: Preserve route files and route-level tests by default; use repository evidence; exclude shared/UI packages and generated artifacts; retain ambiguous files; use a Markdown-only audit inventory  
**Scale/Scope**: Four application directories under `src/web/apps`, their application-specific tests/support files, and their route entry points
