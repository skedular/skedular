# Ownership Inventory: Split Web Products

This inventory is the reviewable source of truth for classifying routes, pages, components, hooks, utilities, providers, queries, generated artefacts, configuration, and documentation before any journey moves between web apps.

## Rules

- Every targeted item must have one target owner or one documented transition owner.
- Shared owners are limited to neutral visual primitives in `@skedular/ui` and neutral runtime foundations in `@skedular/shared`.
- App-specific rules, navigation, permissions, route orchestration, copy, and workflow behaviour stay in the owning app.
- Items with backend-originated return URL risk must be included in the route retirement register before deletion.
- Items with Relay impact require Relay checks or regeneration in the slice that moves them.

## Future Inventory Work

Manual ownership review should challenge any `transition` entry before the first migration slice. The first low-risk pilot should avoid payment, auth, callback, and generated-route deletion risk.

## Shared Extraction Decisions

### Accepted Shared Foundations

- `web/packages/ui/src/app-shell/management-page-shell.tsx`
  - Owner: `@skedular/ui`
  - Reason: neutral management-page layout used by independently owned Teams and Spaces shell slices.
  - Boundary: accepts title, description, empty message, toolbar, actions, and content mode from the owning app; it does not know whether the route is Teams, Spaces, private, marketplace, or customer-facing.
- `web/packages/shared/src/app-shell/organisation-selection.ts`
  - Owner: `@skedular/shared`
  - Reason: neutral list filtering by caller-provided organisation types.
  - Boundary: the helper does not encode `PRIVATE`, `MARKETPLACE`, `webapp-teams`, or `webapp-spaces`; those rules stay in the owning app wrappers.

### Rejected Broad Sharing

- Do not move Teams or Spaces route pages into shared packages. The route purpose, copy, URLs, and organisation ownership are app-specific.
- Do not move WebApp Relay-backed product, team, organisation creation, or storefront feature modules into shared packages as broad modules. Only neutral primitives should move, and GraphQL operations should move with the owning app slice.
- Do not share navigation menu logic yet. Existing navigation mixes account, customer, private organisation, marketplace operator, and Microsoft Teams-hosted concerns and needs separate review before extraction.
