**Feature**: `018-floor-plan-setup-redesign`
**Ownership**: App-local floor plan setup components in each webapp
**Date**: 2026-05-30

## AddFloorPlan

App-local component owned by each webapp. The prop contract and behaviour must stay aligned
across webapp, webapp-teams, and webapp-spaces.

### Props

```typescript
type AddFloorPlanProps = {
  /** Relay preloaded query reference — from addFloorPlan_rootQuery */
  queryReference: PreloadedQuery<addFloorPlan_rootQuery, Record<string, unknown>>;
  /** Called when the component determines the parent must re-run its root query */
  onReloadRequired: () => void;
  /** The location ID this floor plan will belong to */
  locationId: string;
  /** Called when the floor plan has been created successfully */
  onAdded: (locationId: string) => void;
  /** Called when the user cancels or dismisses without saving */
  onCancel: () => void;
  /** Override label for the primary add button. Defaults to "Add floor plan" */
  addLabel?: string;
  /** When true, shows a secondary "Dismiss" button alongside the cancel/add actions */
  showDismiss: boolean;
};
```

### Relay Entry Point

```typescript
// Root query (used by caller to load data; passed as queryReference)
query addFloorPlan_rootQuery(
  $locationId: String!
  $floorPlanId: String!
  $resourcesSortingValues: [ResourceOrderInput!]
) {
  deskResourceType
  roomResourceType
  parkingResourceType
  ...addFloorPlan_resources_query
}
```

The caller (page file in each webapp) is responsible for:

1. Calling `useQueryLoader` / `loadQuery` with `addFloorPlan_rootQuery`
2. Passing the resulting `queryReference` to `<AddFloorPlan>`
3. Providing `onAdded`, `onCancel`, `onReloadRequired`, `locationId`

### Export

Each app continues exporting from its local component folder, for example
`src/components/floorPlan/addFloorPlan`.

## EditFloorPlan

App-local component owned by each webapp. The prop contract and behaviour must stay aligned
across webapp, webapp-teams, and webapp-spaces.

### Props

```typescript
type EditFloorPlanProps = {
  /** Relay fragment key for the floor plan data */
  rootDataRelay: editFloorPlan_query$key;
  /** Relay fragment key for the resources data */
  rootDataResourcesRelay: editFloorPlan_resources_query$key;
  /** Called when the component determines the parent must re-run its root query */
  onReloadRequired: () => void;
};
```

### Relay Fragment Keys

The caller (page file in each webapp) owns the root query that spreads these fragments:

```typescript
// In each webapp's edit page.tsx, the root query must spread:
...editFloorPlan_query
...editFloorPlan_resources_query
```

The caller passes `rootData` (the preloaded query result) as both `rootDataRelay` and
`rootDataResourcesRelay` since both fragments are spread on the same `Query` type.

### Auto-Save Behaviour

`EditFloorPlan` automatically saves changes to:

- Floor plan name (debounced 1000ms after the last keystroke)
- Floor plan image (immediately after successful upload)
- Resource positions on canvas (debounced 1000ms after the last drag release)

No explicit Save button is rendered. A "Close" action is available via `EditorActionBar`.

### Export

Each app continues exporting from its local component folder, for example
`src/components/floorPlan/editFloorPlan`.
