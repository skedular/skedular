# Current-State Review: Teams Pricing, Subscriptions, and Entitlements

## Existing Source of Truth

- `src/shared/Api.Shared.Services/Offering/Offerings.cs` owns the current Teams-style offering codes and plan metadata.
- `src/shared/Api.Shared.Services/Offering/Features.cs` owns current feature descriptions used by offering display models.
- `src/shared/Api.Shared.Services/Models/Offering.cs` represents an active offering state shared across service boundaries.
- `src/organization/shared/Organization.Shared/Database/Entities/OrganizationOffering.cs` is the existing organization-owned persisted subscription/offering record.
- `src/organization/apis/Organization.Api/Services/OrganizationOfferingService.cs` owns current offering update, cancellation-to-Free, renewal scheduling, and organization outbox publishing behavior.
- `src/organization/apis/Organization.Api/GraphQL/Offering/*` exposes current GraphQL offering query and mutation surfaces.

## Current Offering Model

Current V1 offering codes:

- `EarlyBirdV1`
- `FreeTierV1`
- `PayAsYouGoV1`
- `EnterpriseCustomV1`

Current offerings already encode plan name, feature sets, under-price lines, unit price, and max user/location/team counts. Free currently has `MaxUserCount = 10`, `MaxLocationCount = 1`, and `MaxTeamCount = 1`. Pay As You Go and Enterprise Custom use unlimited-style `-1` limits.

## Existing Subscription Behavior

- Organization owns offering state through `OrganizationOffering`.
- Current offering periods are monthly using helper methods in `Offerings.cs`.
- `OrganizationOfferingService.UpdateOfferingAsync` replaces the active offering and schedules renewal through `ScheduleRenewOrganizationOffering`.
- Existing subscriptions must not be mutated by this feature. They are compatibility inputs only.
- Early Bird remains unchanged and honored as-is.

## Existing Entitlement Shape

- Organization publishes organization/offering state through existing event paths.
- Team, Location, and Booking already consume organization events and maintain local projected organization records.
- The intended enhancement is to publish richer pricing/subscription state in those events and keep the current local projection model.
- Other domains should enforce limits using shared `Api.Shared.Services` pricing models/code against their local projected JSON/projection state, not by calling Organization at runtime.

## Existing Frontend Dependency

- `src/web/apps/public-web/src/data/pricing.ts` currently hardcodes public pricing copy, plan names, prices, summaries, product ordering, and product choices.
- That file must stop being the commercial source of truth. It may remain as an adapter to backend-owned catalog data.

## Versioning Decision

Extend the existing V1 offering model for this feature. A new catalog version is not required now because V1 already has the core concepts needed for the first Teams redesign slice: Free, Pay As You Go, Enterprise, Early Bird, monthly offering periods, and existing GraphQL exposure.

Reviewed alternatives:

- New V2 offering version: rejected for this slice because it would add migration pressure without changing the required commercial model.
- Mutating existing `OrganizationOffering` records into the new subscription table: rejected because existing subscriptions must stay unchanged.
- Domain runtime lookups back to Organization for entitlement checks: rejected because current domain boundaries use event-published organization state and local projections.

## Compatibility Decision

- Existing subscriptions stay as-is.
- Existing Free and Early Bird states are read-only compatibility inputs.
- No auto-repair, migration, or downgrade behavior is part of this feature.
- New pricing support is added for new subscription/catalog behavior going forward.

## Generator Impact

- GraphQL schema changes require `scripts/generate-graphql.sh`.
- Organization event protobuf C# output is generated by the consuming `Api.Shared.Clients` build from `api-definitions/events/skedular/*.proto`.
- OpenAPI changes are optional and require `api-definitions/openapi/generate.sh`; web OpenAPI consumers then require `src/web/apps/webapp/scripts/generate.sh`.
- `make generate` remains the preferred entry point when OpenAPI, GraphQL, and web client surfaces may all be affected.

## Structured Logging Coverage

- `PricingCatalogService` logs product filtering decisions and returned offering counts.
- `OrganizationTeamsSubscriptionService` logs offering create/update/read-only compatibility and validation outcomes.
- `PricingEntitlementEvaluator` logs entitlement allow/block decisions with reason codes.
- Active-member qualification routes through the shared evaluator so Organization-owned checks use the same structured allow/block logging as Team, Location, and Booking.
- Renewal workflow charging now uses fixed price before unit-price billing, keeping the Stripe amount decision aligned with the pricing model.
