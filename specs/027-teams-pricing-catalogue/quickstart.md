# Quickstart: Validate Teams Pricing Catalog Redesign

## Prerequisites

- Local dependencies are installed for backend and `src/web`.
- Test infrastructure is available through the repo's existing Docker/Aspire setup.
- Feature implementation has updated source definitions before generated files.

## Regenerate Contracts

Run GraphQL regeneration after backend GraphQL changes:

```bash
scripts/generate-graphql.sh
```

Run OpenAPI generation only if OpenAPI YAML was changed:

```bash
api-definitions/openapi/generate.sh
src/web/apps/webapp/scripts/generate.sh
```

Use `make generate` from the repo root when multiple generated surfaces are affected.

Validated in this implementation run:

- `make generate` completed successfully from the repo root.
- The checkout does not contain `api-definitions/events/generate.sh`; event protobuf C# output is generated by `Api.Shared.Clients` builds from the `.proto` definitions.

## Backend Validation

Run focused unit tests for shared catalog/offering behavior, organization subscription lifecycle, active-user qualification, read-only compatibility, and entitlement decisions:

```bash
dotnet test src/shared/Api.Shared.Services.UnitTests
dotnet test src/organization/apis/Organization.Api.UnitTests
dotnet test src/organization/shared/Organization.Shared.UnitTests
dotnet test src/team/apis/Team.Api.UnitTests
dotnet test src/location/apis/Location.Api.UnitTests
dotnet test src/booking/apis/Booking.Api.UnitTests
```

Run integration tests for persistence, GraphQL contracts, event projection, and cross-domain entitlement paths:

```bash
dotnet test src/organization/domain/Organization.Domain.IntegrationTests
dotnet test src/team/domain/Team.Domain.IntegrationTests
dotnet test src/location/domain/Location.Domain.IntegrationTests
dotnet test src/booking/domain/Booking.Domain.IntegrationTests
```

Expected outcomes:

- Free blocks active user 11, team 2, and location 2.
- Pay As You Go allows unlimited teams and locations and records monthly active users through `OrganizationOfferingActiveMember`.
- Enterprise Capacity allows 100, 500, and 1,000 active users up to capacity and blocks only newly active users beyond capacity.
- Existing subscriptions, including Early Bird and Free, remain unchanged.
- Existing Free organizations retain valid read-only compatibility outcomes.
- Entitlement decisions include stable reason codes and structured logs.

## Web Validation

Run public-web tests after moving pricing pages away from static hardcoded commercial values:

```bash
pnpm --dir src/web --filter public-web test
```

If authenticated web app Relay artifacts are touched, run the relevant web app checks:

```bash
CI=true pnpm --dir src/web --filter webapp lint
CI=true pnpm --dir src/web --filter webapp build
```

Expected outcomes:

- Teams pricing renders Free, Pay As You Go, and Enterprise Capacity from catalog data.
- Plan ordering, features, prices, capacity options, recommended state, and Contact Us behavior come from the catalog.
- No page-specific hardcoded Teams pricing values remain in public-web pricing components/data.
- User-facing copy uses American spelling.
