# Quickstart: Marketplace Pricing Cadence Simplification

## Prerequisites

- Check out branch `047-marketplace-pricing-cadence`.
- Restore repository dependencies and ensure the normal PostgreSQL/test infrastructure is available.
- Confirm the working tree before and after generation so unrelated changes are preserved.

## Contract regeneration

From the repository root, after source contract changes run:

```bash
dotnet build src/shared/Api.Shared.Clients/Api.Shared.Clients.csproj
./scripts/generate-graphql.sh
./src/web/apps/webapp/scripts/generate.sh
pnpm --dir src/web relay
```

Expected result: generated event, GraphQL, OpenAPI/client, and Relay surfaces contain no `BookingCadence` and no removed cadence enum values.

## Validation scenarios

1. Create/read pricing with each supported term. Verify only the ten day-or-longer terms are offered.
2. Verify a Daily non-renewing offer creates one one-day term and no renewal; verify a Daily renewing offer renews daily.
3. Verify a longer purchase term remains the selected term while organization billing/resource slices use the organization billing cycle.
4. Submit booking intervals below, equal to, inside, and above min/max duration. Verify only intervals inside the inclusive range pass duration validation, then verify opening-hours, resource, and conflict rules still apply.
5. Create and purchase an entitlement. Verify cadence is `NotSet`/null, credit and validity rules remain effective, and no subscription/recurring renewal work is created.
6. Run unit tests for cadence mappings, duration validation, renewal branching, entitlement exclusion, and billing slices; run integration tests for persistence/event/schema boundaries; run affected frontend tests.
