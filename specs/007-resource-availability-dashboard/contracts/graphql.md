## New Types

### Scalars / Enums

```graphql
enum ResourceAvailabilityStatus {
  AVAILABLE
  PARTIALLY_BOOKED
  FULLY_BOOKED
  OCCUPIED
  UNAVAILABLE
  BLOCKED
}
```

### ResourceDayView

```graphql
"""
Computed availability view for a single resource on a selected date.
BookingWindows are filtered based on the requesting user's role and the
organization type (see FR-009a in the spec).
"""
type ResourceDayView {
  resourceId: String!
  resourceName: String!
  resourceType: String! # e.g. "RESOURCE_DESK"
  locationId: String!
  locationName: String!
  floorId: String
  floorName: String
  zoneId: String
  zoneName: String
  date: Date!
  status: ResourceAvailabilityStatus!
  openingFrom: Time # null when closed all day
  openingUntil: Time # null when closed all day
  totalOpeningMinutes: Int!
  bookedMinutes: Int!
  bookingWindows: [BookingWindow!]!
}
```

### BookingWindow

```graphql
"""
One booking time window within a resource day view.
Detail fields (bookedByName, bookedByUserId, notes) are null when the
requesting user does not have visibility rights per the organization type rule.
"""
type BookingWindow {
  bookingId: String!
  from: Time!
  until: Time!
  isRecurring: Boolean!
  isCheckedIn: Boolean!
  # Detail fields — null for restricted users
  bookedByName: String
  bookedByUserId: String
  notes: String
}
```

### Result Wrapper

```graphql
type ResourceDayViewResult {
  items: [ResourceDayView!]!
  """
  Opaque key generated by the backend from the canonicalised filter.
  Pass this directly to onResourceAvailabilityChanged to subscribe to
  real-time updates scoped to the exact same filter that produced this result.
  The client must treat this as an opaque string — do not construct it.
  """
  subscriptionKey: String!
}
```

## New Query

```graphql
extend type Query {
  """
  Returns all resource day views matching the given filter and date, sorted by the
  specified order. The full filtered result set is returned in a single response
  (no pagination).

  Tenancy: Only resources belonging to organizations accessible to the requesting
  user are returned. Booking detail visibility is governed by the organization type
  and the user's role.

  Sorting: defaults to RESOURCE_NAME ASC when orderBy is omitted.
  """
  resourceDayViews(filter: ResourceAvailabilityDayFilterInput!, orderBy: ResourceAvailabilityOrderByInput): ResourceDayViewResult!
}
```

---

## New Subscription

```graphql
extend type Subscription {
  """
  Pushes updated ResourceDayView records when the availability of resources
  matching the original query filter changes (new booking, cancellation,
  check-in, or resource status change).

  subscriptionKey: the opaque key returned by resourceDayViews.subscriptionKey.
  Do not construct this key on the client — always use the value from the query result.
  When the filter changes, re-run the query to obtain a new subscriptionKey and
  re-subscribe with it.

  Tenancy: same visibility rules as the originating query apply to pushed events.
  """
  onResourceAvailabilityChanged(subscriptionKey: String!): [ResourceDayView!]!
}
```

## Schema Registration (HotChocolate)

All new types are registered in `Booking.Api`'s existing schema builder alongside the existing booking subscriptions:

```csharp
// In Booking.Api startup / schema configuration (extend existing registrations)
builder.Services
    .AddGraphQLServer()
    // ... existing registrations ...
    .AddType<ResourceDayViewType>()
    .AddType<BookingWindowType>()
    .AddTypeExtension<ResourceAvailabilityQuery>()
    .AddTypeExtension<ResourceAvailabilitySubscription>();
    // ITopicEventSender/ITopicEventReceiver already registered via existing subscriptions
```
